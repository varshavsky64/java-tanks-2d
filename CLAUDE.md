# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Игра-аркада «Танки 2D» в духе Battle City: Java 21 + Swing, Maven, пакет
`io.github.varshavsky64.tanks`. Внешних зависимостей нет вообще — ни библиотек, ни файлов
ресурсов: вся графика рисуется примитивами `Graphics2D`, все звуки синтезируются кодом.

## Команды

```bash
mvn compile
mvn exec:java                                  # запуск из исходников
mvn package && java -jar target/game-tanks-2d-1.0.0.jar
```

## Проверка изменений

**Тестов в репозитории нет** — ни фреймворка, ни `src/test`. Не выдумывай команду запуска
тестов и не сообщай об успехе на основании одной лишь успешной компиляции.

Проверять надо так (оба способа работают, потому что `World` ничего не знает ни про Swing,
ни про звук):

1. **Прогон логики headless.** `new World()` (конструктор без аргументов подставляет
   `Audio.SILENT`) в цикле `world.update()`, поля ввода выставляются прямо в `world.getInput()`.
   Несколько игровых минут ловят исключения, гонки состояний и просадки баланса.
2. **Рендер кадра в PNG.** `new Renderer().render(img.createGraphics(), world)` в
   `BufferedImage` с `-Djava.awt.headless=true`, дальше `ImageIO.write` и просмотр картинки.
   Это единственный способ увидеть регрессию в отрисовке.

Такие прогоны — черновики: складывай их в скретчпад, а не в `src`. **Указывай абсолютный
путь для `ImageIO.write`**: относительный путь резолвится от текущего каталога JVM, и PNG
уже однажды упали прямо в каталог с исходниками.

Чтобы стартовать не с первого уровня, подмени поле `World.level` рефлексией на
`Level.load(n)` — публичного способа нет и заводить его ради теста не надо.

## Архитектура

### Слои

`Main` → `GamePanel` (Swing) → `World` (правила) → сущности (`Entity` и наследники).

Ключевое свойство: **`World` не зависит ни от Swing, ни от звуковой карты**. Звук идёт
через интерфейс `Audio` (`SoundEngine` в игре, `Audio.SILENT` в прогонах), отрисовки в
`World` нет вообще. Ломать этот шов нельзя — на нём держится вся проверка изменений.

### Игровой цикл

`javax.swing.Timer` на 16 мс, то есть **обновление и отрисовка идут на EDT последовательно**.
Гонок между `update()` и `paintComponent()` нет по построению, поэтому в коде нет никакой
синхронизации. Перенос обновления в отдельный поток потребует пересмотра всего этого.

### Кто за что отвечает

`update()` у сущностей только двигает объект. **Все столкновения, урон, очки и звук
разрешает `World`** — искать логику взаимодействий надо там, а не в `Bullet` или `Tank`.

### Карты и геометрия

Клетка 16 px, поле 44×32 клетки (704×512), панель 150 px, танк 32 px = ровно 2 клетки.

Карты в `Level.MAPS` пишутся в **укрупнённой сетке 22×16**, где один символ — блок 2×2
клетки (размер танка), и разворачиваются при загрузке. Отсюда два следствия: карты легко
править на глаз, а кирпич крошится по четвертинкам блока. Размеры проверяются в `Level.load`,
опечатка в длине строки даёт понятное исключение. Символы: `.` пусто, `#` кирпич, `S` броня,
`W` вода, `T` кусты, `I` лёд, `B` база.

Уровни зациклены через `Math.floorMod`, но `levelIndex` растёт дальше и подкручивает
сложность в `fillSpawnQueue`.

### Движение

При смене направления танк **прижимается к сетке по перпендикулярной оси**
(`Tank.alignToGrid`). Без этого в проходы шириной в танк не попасть — если правишь движение,
это трогать в последнюю очередь.

### Модель урона

Один выстрел выбивает **одну клетку в глубину и две поперёк** (ровно ширина танка) —
см. `World.damageArea`, зона считается от точки касания, а не от габаритов снаряда.
Поэтому блок стены пробивается двумя попаданиями, а пробоина сразу проезжая.
Не заменяй это на `Rectangle.grow` от всего снаряда — так уже было, дыры получались вдвое шире.

### Подводные камни

- `Bullet.kill()` уменьшает счётчик `activeBullets` у владельца. Гасить снаряд присваиванием
  `alive = false` нельзя — у танка навсегда пропадёт слот выстрела.
- `World` мутирует списки во время обхода (граната из `collectPowerUps` доходит до
  `destroyEnemy`, который трогает `powerUps`). Обходы идут по копиям — это не лишняя
  осторожность, а лечение реального `ConcurrentModificationException`.
- `Renderer` проходит по сетке дважды: кусты рисуются **после** танков, чтобы прятать их.
  Флаг `treesLayer` в `drawTiles`.

### Звук

`SoundEngine` синтезирует все эффекты в память при старте (меандр, синус, сглаженный шум)
и микширует активные голоса в одну `SourceDataLine` фоновым демон-потоком. Так сделано
потому, что одиночный `Clip` не умеет накладывать звук сам на себя. При отсутствии
звуковой карты движок молча уходит в тишину.

### Где крутить баланс

Константы вверху `World` (число врагов на поле, интервал спавна, жизни, частота бонусных
танков), таблица характеристик в `EnemyTank.Type`, прокачка игрока в `PlayerTank.applyUpgrade`,
скорострельность врагов в конструкторе `EnemyTank`.
